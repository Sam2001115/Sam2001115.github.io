01. Objective

Build a low-cost, always-on room security monitor that detects intrusions and delivers instant alerts to my phone via Telegram — regardless of where I am. The system needed to be wireless, self-monitoring, and deployable without a fixed position in the room.

03. Features

Intrusion Detection

HC-SR04 scans the room continuously. A multi-ping filter confirms real movement before triggering an alert.

Telegram Alerts

Instant message sent to 2 Telegram chat IDs with intrusion timestamp and duration. Alert within 2 seconds of detection.

Remote Arm / Disarm

Send /start or /status commands back to the Telegram bot to arm, disarm, or check room status remotely.

NTP Real-Time Clock

OLED shows live time in 12-hour AM/PM format when no alert is active. Auto-adjusts for AEST/AEDT daylight saving.

Web Dashboard

HTTP Basic Auth dashboard — arm/disarm, adjust detection threshold, and view alert history from any browser on the network.

Healthchecks.io Heartbeat

ESP32 pings Healthchecks.io every minute. If 3 consecutive pings are missed, an email downtime alert is sent automatically.

Threshold Adjustment

Two physical buttons adjust the detection range directly on the device. OLED gives live feedback. Threshold persists across reboots via Preferences.

Multi-Network WiFi

Auto-connects to up to 3 saved networks with reconnect logic — works at home, office, or wherever it's deployed.

04. Challenges

Challenge 1 — Silent Failure: If the device lost power or WiFi, there was no way to know the room was unprotected. A standard security device that fails silently is worse than no device at all.

Challenge 2 — False Triggers: Ultrasonic sensors are sensitive to minor environmental changes — air currents, reflections, sensor noise. A naive implementation triggered alerts constantly on non-events.

Challenge 3 — Dynamic Placement: The device doesn't have a fixed position in the room. Re-flashing the firmware every time the detection range needed adjusting was completely impractical.

Challenge 4 — No Clock Without Internet: Timestamps in Telegram alerts and the web dashboard were meaningless without real wall-clock time. The ESP32 has no RTC, so time had to come from the network — and needed to handle Australian daylight saving automatically.

05. Solutions

Silent Failure — Healthchecks.io: The ESP32 sends a heartbeat ping to Healthchecks.io every minute. If the service misses three consecutive pings — due to power loss, WiFi drop, or crash — it automatically sends a downtime email alert. The device can't go silently offline.

False Triggers — Ping Filter Algorithm: Rather than acting on any single sensor reading, the firmware requires a consistent change in distance across multiple consecutive pings before confirming an intrusion. Noise and one-off reflections are ignored. Only a sustained, real presence triggers the alert.

Dynamic Range — Physical Buttons + Persistent Storage: Two push buttons increment and decrement the detection threshold directly on the device. The SSD1306 OLED provides real-time feedback showing the current range setting. The threshold is saved to non-volatile flash storage via the ESP32's Preferences library — it survives reboots and power cuts.

Real-Time Clock — NTP + Auto Timezone: The ESP32 syncs time over WiFi using NTP on boot. The timezone is set using the POSIX string for automatic AEST/AEDT switching — no manual daylight saving adjustment ever needed.

// Automatic AEST/AEDT daylight saving — no manual offset needed setenv("TZ", "AEST-10AEDT,M10.1.0,M4.1.0/3", 1); tzset(); configTime(0, 0, "pool.ntp.org"); // OLED clock display — 12-hour AM/PM format strftime(timeStr, sizeof(timeStr), "%I:%M %p", &timeinfo);

Web Dashboard: A lightweight HTTP server runs on the ESP32, protected by Basic Auth. From any browser on the same network, the dashboard shows live sensor distance, armed/disarmed state, detection threshold, and a timestamped alert history log.

08. Lessons Learned

Silent Failure Is Unacceptable in Security Systems

A device that fails without telling you is worse than no device. Healthchecks.io solved this elegantly — the heartbeat model means the system actively proves it's alive rather than passively hoping nothing goes wrong.

Filter Sensor Data — Never Act on Raw Readings

A single ultrasonic ping is unreliable. Environmental noise, reflections, and interference all cause spurious readings. Requiring consistency across multiple consecutive readings before acting eliminated false positives entirely.

Hardcoded Configuration Is a Maintenance Problem

Re-flashing firmware to change a detection threshold is impractical. Physical buttons + persistent Preferences storage made the device truly self-contained and adjustable without a laptop.

POSIX Timezone Strings Handle DST Automatically

Hardcoding UTC+10 breaks for half the year in Melbourne. The POSIX TZ string AEST-10AEDT,M10.1.0,M4.1.0/3 handles all daylight saving transitions automatically — the right way to do timezones on embedded systems.
