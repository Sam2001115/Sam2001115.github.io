01. Objective

Implement a fully functional vending machine controller in bare-metal C on an AVR microcontroller as the EEET2256 major project. The system manages a complete purchase cycle — item selection via keypad, coin accumulation, item dispensing, and change calculation — using a finite state machine (FSM) architecture with LED and 7-segment display feedback.

No RTOS, no libraries beyond the AVR standard — all peripheral control (GPIO, timers, interrupts) written from register level.

02. Technology Used

Hardware
ATmega328P (AVR) 4×4 Matrix Keypad 7-Segment Display (multiplexed) LED Array (status indicators) OUSB Development Board
Software
Bare-metal C AVR-GCC Finite State Machine (FSM) Timer1 (keypad debounce & display mux) INT0 Interrupt (coin insert)

03. State Machine Design

The controller is implemented as a 7-state FSM. Each state has defined entry actions, active behaviours, and transition triggers:

StateDescriptionTransition Trigger
IDLEDisplay welcome, all LEDs offAny keypad press
SELECTShow item menu, await selectionValid item key pressed
PRICE_SHOWDisplay selected item priceAuto (1s timeout)
INSERT_COINAccumulate coins, show balanceBalance ≥ price
DISPENSETrigger dispense motor, LED flashAuto (dispense delay)
CHANGECalculate & display change owedAuto (change paid out)
ERRORFlash error LED, buzzer pulseReset key or timeout
// FSM core (C, AVR) typedef enum { IDLE, SELECT, PRICE_SHOW, INSERT_COIN, DISPENSE, CHANGE, ERROR } State_t; void fsm_tick() { switch (current_state) { case IDLE: handle_idle(); break; case SELECT: handle_select(); break; case INSERT_COIN:handle_insert(); break; case DISPENSE: handle_dispense(); break; case CHANGE: handle_change(); break; // ... } }

04. Key Implementation Details

Keypad Scanning: The 4×4 matrix is scanned column-by-column using Timer1 ISR at 1 ms intervals. Row lines are read after each column is driven low, with 10 ms debounce logic in software to suppress contact bounce.

Display Multiplexing: The 7-segment display is multiplexed across four digits using the same Timer1 ISR — each digit is active for one scan period in turn, achieving flicker-free display at ~250Hz effective refresh.

Coin Detection: Each coin insertion triggers an INT0 external interrupt. The ISR adds the coin denomination to the balance register and updates the display immediately.

Change Calculation: Uses a greedy algorithm — dispenses the largest denomination coin first, iterating down until change balance reaches zero. Coin counts stored in EEPROM to survive power cycles.

06. Lessons Learned

FSMs Scale Cleanly With Discipline

Structuring the controller as a proper FSM — no nested if-else spaghetti — made debugging and extending states straightforward. Every new feature is just a new state with defined transitions.

ISR Code Must Be Minimal

Putting too much logic in the coin ISR caused timing conflicts with the display multiplexer. The fix was to set a flag in the ISR and process the coin in the main loop — a critical embedded pattern.

Register-Level Peripheral Control Builds Real Understanding

Writing directly to TCCR1B, OCR1A, and EIMSK instead of using Arduino wrappers forced a thorough understanding of how timers, interrupts, and GPIO actually work on AVR silicon.
