PROJECT:
OUSB_SIMULATOR

✓ COMPLETED EMBEDDED SYSTEMS SOFTWARE C++ AVR ARCHITECTURE
// 01

Objective

Design and implement a high-fidelity software simulator that accurately emulates the hardware behaviour of the Open USB (OUSB) board — a microcontroller platform based on the AVR ATmega2560 architecture used in RMIT's embedded systems curriculum.

The simulator must replicate the board's port register system at the bitwise level, enforce a strict error-precedence validation engine, and process instruction files through a custom command parser — all with 100% accuracy against the physical hardware specification.

Challenges

1. Exact Register Emulation: The OUSB board uses 8-bit hardware port registers (PORTA, PORTB, PORTC). Each bit corresponds to a physical I/O pin. Replicating this at the software level required individual bit-level control using bitwise operations — the same way hardware works.

2. Strict Error Precedence: The hardware spec defines a rigid order in which errors must be detected and reported. A wrong number of arguments must be caught before an invalid port name, which must precede an out-of-range pin, and so on. Implementing this precedence chain without any leakage between cases was the most demanding design requirement.

3. Command Parser Accuracy: The simulator had to handle instruction files with multiple command types, variable argument counts, and edge cases — whitespace variations, invalid tokens, mixed-case input — while matching hardware output exactly, character for character.

4. Zero-Hardware Testing: With no physical OUSB board available for continuous comparison, all validation had to be done against the documented specification. Any deviation in output format — even a trailing space — counted as incorrect.

// 04

Solutions

Register Emulation — C++ Classes + Bitwise Ops:

// Set pin high: PORTA |= (1 << pin); // Clear pin low: PORTA &= ~(1 << pin); // Read pin: bool state = (PORTA >> pin) & 1; class Port { uint8_t reg = 0x00; // 8-bit virtual register public: void set(int pin) { reg |= (1 << pin); } void clear(int pin) { reg &= ~(1 << pin); } bool read(int pin) { return (reg >> pin) & 1; } uint8_t value() { return reg; } };

Error Precedence — Validation Engine: Implemented a structured validation chain that runs before any instruction executes. Checks fire in strict priority order: argument count → port validity → pin range → data type → value range. The first failure triggers its specific error code and halts further processing — exactly matching hardware behaviour.

File I/O — Custom Command Parser: A line-by-line parser reads the instruction file, tokenises each line by whitespace, maps tokens to port/pin operations, updates the virtual registers, and outputs the LED/switch state to console after each instruction — matching the hardware's serial output format precisely.

// 05

Results

✓ Outcome

Simulator fully operational — accurately mirrors physical OUSB board behaviour across all tested instruction sets. Error precedence engine correctly prioritises all failure modes in the specified order. 100% output accuracy against hardware specification.

✓ Validation

Tested against the complete set of documented edge cases: invalid port names, out-of-range pins, malformed argument counts, mixed-case input, and boundary values. All cases produce output identical to the hardware reference.

// 06

Lessons Learned

Abstraction

Good class abstraction enables hardware emulation. One C++ class per port made the simulation accurate, testable, and extensible.

Error Design

Error ordering is part of the specification, not a minor detail. A validation engine that respects precedence is fundamentally different from one that doesn't.

Bitwise Operations

Bitwise operations are the language of hardware. Understanding OR, AND, NOT, and XOR at the bit level is essential for any embedded systems work.

Simulation Value

Simulators are powerful development tools. Testing firmware logic without hardware accelerates development and catches issues before they reach silicon.
