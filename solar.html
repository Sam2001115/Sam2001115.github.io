Design and build a fully functional solar energy monitoring and management system capable of real-time power measurement, automated relay control, environmental sensing, and live data visualisation — accessible from any device without a router.

The system targets the real-world challenge of small-scale solar integration, demonstrating hybrid charging management, demand response concepts, and energy data telemetry relevant to the Australian renewable energy sector.

03. The Challenges

Challenge 1 — GPIO9 Strapping Pin: GPIO9 on the ESP32-C3 is a strapping pin tied to boot mode selection. Attempting to drive it LOW as a PWM output for fan control caused boot failures.

Challenge 2 — ADC1 Pin Shortage: The ESP32-C3 SuperMini only exposes ADC1 channels. With GPIO0 (current), GPIO1 (voltage), and GPIO20 (DHT22) already assigned, no free ADC1 pin remained for independent solar voltage monitoring.

Challenge 3 — Relay Boot Flicker: GPIO pins float for a brief window before the Arduino framework initialises, causing relays to energise momentarily on every power-up — an unsafe condition for connected loads.

Challenge 4 — ACS712 Zero-Current Offset Drift: The ACS712 midpoint should sit at 1.65V (half of 3.3V supply), but temperature and supply variation pushed the actual offset to 0.661V, producing a consistent -1.77A reading at zero current.

Challenge 5 — Voltage Divider Ratio Miscalculation: The theoretical resistor ratio did not match real-world readings due to component tolerance stack-up, causing voltage measurements to be significantly off.

Challenge 6 — DHT22 NaN on First Read: The DHT22 consistently returned NaN on the first read after power-on, regardless of wiring or pull-up resistor value.

Challenge 7 — TFT Display Ghosting: When switching between TFT screens with different text sizes, residual pixels from the previous render remained visible, producing a ghosting effect.

04. The Solutions

GPIO9 — Physical Switch: GPIO9 cannot be used as a software output on the ESP32-C3. The fan was moved to a physical slide switch on the 5V power line, bypassing the pin entirely. An ADS1115 I2C ADC is planned for v2 to free up GPIO assignments.

// Relay boot-safe init — ESP-IDF before Arduino pinMode gpio_reset_pin (RELAY1_PIN); gpio_set_direction(RELAY1_PIN, GPIO_MODE_OUTPUT); gpio_set_level (RELAY1_PIN, 0); // hold LOW before Arduino init pinMode (RELAY1_PIN, OUTPUT);

ACS712 Calibration: Raw ADC readings at confirmed zero current were used to determine the true midpoint offset (0.661V). A ±0.15A deadband filter was applied to suppress noise around the zero crossing.

// ACS712 — empirical calibration OFFSET_V = 0.661V // measured at zero current SENS = 0.185 V/A // ACS712-5A sensitivity DEADBAND = ±0.15A // noise floor filter V_RATIO = 23.0 // empirical (not theoretical)

DHT22 Fix: A mandatory 2-second delay between Serial.begin() and dht.begin() in setup() allows the sensor to stabilise before the first read is attempted.

TFT Ghosting Fix: Instead of a full-screen clear on every refresh, per-zone fillRect() calls clear only the area being redrawn. This eliminates ghosting while keeping the refresh fast and flicker-free.

WiFi Interface — Access Point Mode: The ESP32-C3 broadcasts its own network with no router required. Any device connects to SolarMonitor at 192.168.4.1 for live data and relay control.

07. Lessons Learned

Always Check Strapping Pins First

GPIO9 on the ESP32-C3 looks like a normal IO pin in the datasheet, but it controls boot mode. Assigning it to fan PWM caused boot failures. Always cross-reference the strapping pin table before assigning any IO.

Calibrate Sensors Empirically, Not Theoretically

Both the ACS712 offset and the voltage divider ratio were significantly off from theoretical values in the real build. Resistor tolerance and supply variation made empirical calibration against a reference meter essential.

Initialise GPIO Before the Arduino Framework

Relay boot flicker was eliminated by using ESP-IDF gpio functions to force pins LOW before Arduino's pinMode() runs. For any safety-critical output, don't rely on the Arduino init sequence alone.

Sensors Need Stabilisation Time

The DHT22 requires a stabilisation period after power-on. A simple 2-second delay in setup() fixed persistent NaN readings. Always check sensor datasheets for startup timing requirements.

Plan ADC Pin Budget Before Committing to a Module

The ESP32-C3 SuperMini only exposes ADC1 channels. Running out of ADC pins mid-build meant solar voltage had to mirror battery voltage in v1. Plan the full pin budget against the module's datasheet before starting layout.
